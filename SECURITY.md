# Security Policy

OpenBackend is currently alpha software. It is suitable for local development, internal prototypes, and controlled self-hosted trials after hardening, but it is not yet a hardened multi-tenant cloud service.

## Supported Versions

| Version | Status |
| --- | --- |
| 0.1.x alpha | Security fixes accepted |

## Reporting a Vulnerability

Please do not publish sensitive exploit details in a public issue before maintainers have had time to respond.

For now, report suspected vulnerabilities through a private GitHub security advisory on the repository. If that is unavailable, open a minimal public issue that says you have a security report without including exploit steps, secrets, payloads, or target details.

Expected response target:

- Initial acknowledgement: 7 days.
- Triage update: 14 days.
- Fix or mitigation plan: depends on severity and reproducibility.

## Clean-Room Boundary

Do not submit copied proprietary backend code, branding, docs, assets, or reverse-engineered service internals. OpenBackend accepts original implementation work and permissively licensed open-source dependencies with attribution.
